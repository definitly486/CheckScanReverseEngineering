# CheckScan APK static analysis

This workspace is generated by `decompile_checkscan.sh`.

## Important output

- `apk_analysis/metadata.txt` — package/version/manifest metadata.
- `apk_analysis/jadx/` — decompiled Java/Kotlin sources.
- `apk_analysis/apktool/` — decoded manifest, resources and smali.
- `apk_analysis/interesting_strings.txt` — URL/auth/network-related strings.
- `api/hosts/all_url_candidates.txt` — URL candidates found in static data.
- `api/hosts/unique_hosts.txt` — unique hostnames.
- `api/endpoints/route_candidates.txt` — route and Retrofit annotation references.
- `api/network/client_setup.txt` — HTTP client setup references.
- `api/authentication/auth_references.txt` — auth/session/token references.
- `api/api_discovery.txt` — combined searchable evidence report.

## Interpretation

Static analysis can reveal hard-coded hosts, paths, request DTOs and client
configuration. It cannot guarantee that every backend route is found:
some routes may be assembled dynamically, delivered by remote configuration,
or only appear in runtime responses. URL matches may also be analytics,
crash reporting, CDN or web links rather than application APIs.

Treat a route as confirmed only after tracing its call site, HTTP method,
headers, query parameters/body and response model. Do not put personal
credentials, SMS codes, access tokens, cookies, HAR/PCAP captures or account
responses in a public repository.

This script does not authenticate to CheckScan or bypass TLS protections.
